# Project guidance

- This is a Python CLI for preparing a Tamimi grocery cart. `shopping.py` owns the workflow, SQLite schema, and CLI; `README.md` documents usage.
- Use the existing Browser Use session (`.browser-profile`) for shopping. Do not add Ego or replay `Shoppingsteps.json` literally; it is a navigation reference.
- Both `shop` agents use `ChatOpenAI` with `OPENAI_API_KEY`, `OPENAI_BASE_URL`, and `OPENAI_MODEL` from `.env.local` or the environment. The current OpenAI-compatible endpoint is `https://cli.fayaa92.sa/v1`; use the model name exposed by that server, with image and structured JSON output support. The default model is `gpt-4.1`. No Browser Use API key or Codex subscription adapter is required. Never expose or commit API keys.
- The persistent profile and `.browser-profile/storage-state.json` intentionally work together to retain session cookies and storage across restarts. The warning about supplying both is expected; snapshot values take precedence over matching profile values. Each normal run updates the same snapshot, not a session archive. Close other setup/shop browsers before starting.
- Telegram runs headlessly in Docker on SSH host `fayaalink`, under `/srv/docker/agent-shopping`. Compose service `bot` uses image `agent-shopping-bot` and container `agent-shopping-bot-1`. Keep `hostname: shopping-browser` for both the bot and one-off browser containers: Chromium profile locks depend on hostname. Stop the bot and verify no active shopping/browser process before using its profile elsewhere. Remove stale singleton locks only after verifying no browser owns them.
- Log in on the Mac with `uv run python shopping.py setup`; transfer only `.browser-profile/storage-state.json`, not the Mac Chromium profile. Server state lives under `server-data/browser-profile/` and `server-data/data/`. Runtime secrets are in `.env.server`; never expose them or include secrets/state in the image.
- `shopping.db` is the sole source of truth for the active list, preferred products/SKUs, approved alternatives, price caps, observed prices, and purchase confirmations. Manage list items with the `add`, `remove`, and `list` CLI commands.
- Preserve existing cart items and add only missing quantities across validated qualifying products. Quantities are purchasable units: 10 packs of 3 cups = 10 cart units, not 30. Prefer exact products, then suitable approved alternatives; otherwise the agent chooses the nearest suitable product from visible evidence. Match type semantically, not by identical names. Honor all explicit attributes and caps; unspecified brand/flavor/package is flexible, with no mainstream-brand requirement. Require unavailability evidence only for saved preferences/alternatives and a required package quantity only for an explicit package need. Automatic selections record `matches_request`, `match_reason`, and quoted `match_evidence` per candidate; code validates quotes, saved brand, numeric package needs, and an explicit cap or the observed 115% comparison cap. Semantic interpretation remains agent judgment. Report the chosen product/package clearly. Validate evidence before adding and again against recorded selection/final cart; never exceed a cap. Jev may rank explicitly approved alternatives; exact known products use deterministic rules. Recover item search/navigation failures with at most three distinct actions, then mark unresolved and continue. Account/fulfillment, CAPTCHA, unsafe actions, checkout, and product-plus failures stop the run. Only `confirm-purchase` promotes validated automatic selections from that saved attempt into alternatives.
- Product additions use `add_product_plus` and `PRODUCT_PLUS_SELECTOR`: `[class*="ProductDetails__ImgAndCarouselDiv"] svg[class*="Counter__StyledAddToCart"]`. Require exactly one match. Avoid full generated class names, positional wrapper chains, or an SVG `circle` selector; those failed on the live yogurt page. Investigate selector failures by reading current product markup without clicking cart controls.
- `telegram_bot.py` exposes `/add`, `/clear`, `/list`, `/shop [location]`, `/help`, and `/start`, authorized by `TELEGRAM_ALLOWED_USER_ID` in private chats. `/add` sets target quantity; `/clear` clears the saved list/preferences/alternatives while preserving purchase history, observed prices, and the live cart. Block list mutations during shopping; never automatically retry shopping or replay pending updates after restart.
- Shopping CLI results use command-local `--result-file`; exceptions and `no_summary` include redacted diagnostics. Telegram replies use canned reasons and a run reference, never raw diagnostic text. Private rotating diagnostics are saved to `/data/shopping-diagnostics.jsonl` (server: `server-data/data/shopping-diagnostics.jsonl`). Inspect the referenced record before changing guards, selectors, models, or step limits. Missing summary means incomplete, not verified success.
- Both agents use `enable_signal_handler=False`; application SIGTERM handling awaits browser cleanup. Preserve intentional `keep_alive=True` reuse between readiness and shopping agents and call `browser.kill()` during cleanup.
- The cart's checkout button may be used to select the earliest available slot. Stop there for human approval: never continue to payment, enter card details, or place an order. Record a purchase only after explicit confirmation with `confirm-purchase`.
- Run `uv run --no-sync python -m unittest -q` for local verification. Do not run `shopping.py shop` or change the live Tamimi cart as a test.
- `docker_smoke_test.py` checks native headless Chromium, session restoration, and product-plus selection against a localhost DOM fixture. `docker_profile_regression.py` checks cross-container profile recovery with the stable hostname. Use isolated profiles for these checks; live selector verification must remain read-only. A successful startup or selector check does not establish end-to-end shopping success.
